## 2. Frontend Architecture

### Technology Stack
- **Framework**: Next.js 16+ (App Router)
- **Language**: TypeScript (strict mode)
- **State Management**: TanStack Query v5+
- **Styling**: Tailwind CSS v4 + shadcn/ui
- **Forms**: React Hook Form + Zod
- **HTTP Client**: Axios
- **i18n**: Intlayer (English, Vietnamese, Japanese)
- **Real-time**: Socket.IO Client

### Directory Structure
```
frontend/src/
├── app/[locale]/                    # App Router with i18n
│   ├── (auth)/                      # Auth routes group
│   ├── dashboard/                   # Student dashboard
│   ├── practice/                    # Practice sessions
│   ├── lessons/                     # Lesson content
│   ├── teacher/                     # Teacher dashboard
│   ├── admin/                       # Admin panel
│   └── page.tsx                     # Root page
├── components/
│   ├── ui/                          # shadcn/ui components
│   ├── layouts/                     # Layout components
│   └── providers/                   # React Query, Socket, etc.
├── hooks/
│   └── api/                         # Custom hooks (useQuery, useMutation)
├── libs/
│   ├── apiClient.ts                 # Axios instance
│   ├── queryKeys.ts                 # TanStack Query keys
│   └── socket.ts                    # Socket.IO client
```

```
React Component
    ↓

    ↓

    ↓
NestJS Backend
```

## 4. Database Design (PostgreSQL)

### Core Tables

#### Users
```sql
users (
  id UUID PRIMARY KEY
  email VARCHAR UNIQUE NOT NULL
  password_hash VARCHAR NOT NULL
  full_name VARCHAR
  role ENUM (STUDENT, TEACHER, ADMIN)
  created_at TIMESTAMP
  updated_at TIMESTAMP
)
```

#### Students
```sql
students (
  id UUID PRIMARY KEY
  user_id UUID FOREIGN KEY → users.id
  jlpt_goal_level ENUM (N1, N2, N3, N4, N5)
  current_mastery_json JSONB
  created_at TIMESTAMP
)
```

#### Questions
```sql
questions (
  id UUID PRIMARY KEY
  level ENUM (N1, N2, N3, N4, N5)
  section VARCHAR (Vocabulary, Grammar, Reading, Listening)
  skill VARCHAR (Author's Opinion, Inference, etc.)
  difficulty ENUM (Easy, Medium, Hard)
  question_content TEXT
  explanation TEXT
  choices JSONB
  correct_answer VARCHAR
  created_at TIMESTAMP
)
```

#### QuestionAttempts
```sql
question_attempts (
  id UUID PRIMARY KEY
  student_id UUID FOREIGN KEY → students.id
  question_id UUID FOREIGN KEY → questions.id
  student_answer VARCHAR
  is_correct BOOLEAN
  time_spent_seconds INTEGER
  attempted_at TIMESTAMP
)
```

#### SkillMastery
```sql
skill_mastery (
  id UUID PRIMARY KEY
  student_id UUID FOREIGN KEY → students.id
  jlpt_level ENUM
  skill VARCHAR
  correct_answers INTEGER
  total_attempts INTEGER
  mastery_percentage DECIMAL
  last_updated TIMESTAMP
)
```

#### SRSItems
```sql
srs_items (
  id UUID PRIMARY KEY
  student_id UUID FOREIGN KEY
  question_id UUID FOREIGN KEY
  content_type ENUM (QUESTION, VOCABULARY, GRAMMAR)
  stage INTEGER (0-5)
  last_reviewed TIMESTAMP
  next_review TIMESTAMP
  interval_days INTEGER
  ease_factor DECIMAL
  created_at TIMESTAMP
)
```

#### DailyLearningPlans
```sql
daily_learning_plans (
  id UUID PRIMARY KEY
  student_id UUID FOREIGN KEY
  plan_date DATE
  activities JSONB (array of activities with time estimates)
  total_time_minutes INTEGER
  created_at TIMESTAMP
)
```

#### Lessons
```sql
lessons (
  id UUID PRIMARY KEY
  title VARCHAR
  jlpt_level ENUM
  section VARCHAR
  video_url VARCHAR
  transcript TEXT
  vocabulary JSONB
  grammar_points JSONB
  quiz_questions UUID[] (references questions)
  created_at TIMESTAMP
)
```

#### Classes
```sql
classes (
  id UUID PRIMARY KEY
  name VARCHAR
  teacher_id UUID FOREIGN KEY → users.id
  jlpt_level ENUM
  school_id UUID FOREIGN KEY
  created_at TIMESTAMP
)
```

#### ClassEnrollments
```sql
class_enrollments (
  id UUID PRIMARY KEY
  class_id UUID FOREIGN KEY → classes.id
  student_id UUID FOREIGN KEY → students.id
  enrolled_at TIMESTAMP
)
```

#### Attendance
```sql
attendance (
  id UUID PRIMARY KEY
  class_id UUID FOREIGN KEY
  student_id UUID FOREIGN KEY
  attendance_date DATE
  status ENUM (Present, Absent, Late, Excused)
  created_at TIMESTAMP
)
```

```
/api/v1
├── /auth
│   ├── POST /register
│   ├── POST /login
│   ├── POST /logout
│   └── POST /refresh-token
│
├── /students

│   ├── GET /me/weak-areas           # Weak areas
│   ├── GET /me/daily-plan           # Today's learning plan
```

## 6. Authentication & Authorization

### Authentication Flow
```
User Credentials
    ↓
POST /auth/login
    ↓
Validate Email/Password
    ↓
Generate JWT (Access + Refresh tokens)
    ↓
Return tokens in response
    ↓
Store tokens in HttpOnly cookie (Frontend)
    ↓
Each request includes Authorization header
    ↓
NestJS Guard validates JWT
    ↓
Request proceeds if valid
```

### Authorization Levels
```
Public Routes
├─ /auth/register
├─ /auth/login
└─ /home (public homepage)

Student Routes (Authenticated Student)
├─ /dashboard
├─ /practice
├─ /lessons
└─ /profile

Teacher Routes (Authenticated Teacher)
├─ /classes
├─ /students
└─ /analytics

Admin Routes (Authenticated Admin)
├─ /users
├─ /schools
└─ /reports
```

## 8. Caching Strategy (Redis)

### Cache Keys
```
skill_mastery:{studentId}:{level}
├─ TTL: 1 hour
├─ Updated on: Practice completion, SRS review

daily_plan:{studentId}:{date}
├─ TTL: 24 hours
├─ Updated on: Daily regeneration (00:00)

recommendations:{studentId}
├─ TTL: 30 minutes
├─ Updated on: Practice completion

user_session:{sessionId}
├─ TTL: 7 days (or logout)
```

## 9. Background Jobs (Bull Queue)

### Scheduled Jobs
```
1. Calculate Mastery Scores (Every 10 minutes)
   └─ Recalculate skill_mastery for all students

2. Generate Daily Plans (00:00 daily)
   └─ Create daily_learning_plan for active students

3. Update SRS Schedules (Every hour)
   └─ Find SRS items ready for review

4. Send Notifications (Various triggers)
   └─ Practice reminder, achievement, etc.

5. Database Cleanup (Weekly)
   └─ Archive old data, optimize tables
```

## 11. Security Measures

- **Authentication**: JWT with HttpOnly cookies
- **Authorization**: Role-based access control (RBAC)
- **Encryption**: HTTPS/TLS for all data in transit
- **Database**: Prepared statements (Prisma ORM)
- **Rate Limiting**: Redis-based rate limiter
- **CORS**: Configured for allowed origins
- **Helmet**: HTTP headers security
- **Validation**: class-validator for all DTOs
- **Secrets**: Environment variables (never in code)

---

## 12. Scalability Considerations

1. **Horizontal Scaling**: Multiple NestJS instances behind load balancer
2. **Database Replication**: Read replicas for analytics queries
3. **Caching Layer**: Redis for frequently accessed data
4. **CDN**: Static assets distributed globally
5. **Background Jobs**: Bull queue for async operations
6. **Microservices** (Future): Separate recommendation engine as microservice
