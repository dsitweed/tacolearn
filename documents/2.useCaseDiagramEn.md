## 3. Detailed Use Case: UC-002 (Start Practice Session)

### Actors
- **Primary**: Student
- **Secondary**: System

### Preconditions
- Student is logged in
- Student has viewed available practice options

### Main Flow
1. Student selects practice type (Targeted, Mixed, Weak Areas, Previous Mistakes)
2. Student selects JLPT level
3. Student selects section/skill
4. Student sets number of questions
5. System validates selection
6. System generates practice set based on student's skill levels
7. System displays first question
8. Student proceeds to answer questions

### Postconditions
- Practice session created in database
- Timer started (if enabled)
- Question attempts recorded

### Alternative Flows

**A1: Adaptive Practice**
- Instead of manual selection, student chooses "Adaptive"
- System determines questions from weak areas
- System creates optimal practice set

**A2: Previous Session Continue**
- Student has incomplete session
- Student can resume from where they left off

## 7. Constraints & Business Rules

### BC-1: Mastery Calculation
- Minimum 5 attempts required to establish baseline mastery
- Recent attempts weighted 2x
- Mastery = (Correct Answers / Total Attempts) × 100

### BC-2: Weak Area Detection
- Red Flag: Mastery < 50%
- Warning: 50% ≤ Mastery < 65%
- Good: 65% ≤ Mastery < 80%
- Excellent: Mastery ≥ 80%

### BC-3: Daily Plan Generation
- Plan generated once per day (12:00 AM)
- Plan includes: SRS due today + adaptive practice + lessons
- Max total time: 2 hours recommended
- Priority: weak areas first

### BC-4: SRS Intervals
- Initial review: 1 day
- Second: 3 days
- Third: 7 days
- Fourth: 14 days
- Fifth: 30 days
- Graduation: No review (unless confidence drops)

### BC-5: Recommendations
- Based on: Student mastery, difficulty, recency, JLPT importance
- Updated: After each practice session
- Displayed: On dashboard and practice interface
